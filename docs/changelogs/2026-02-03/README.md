# Changelog - 2026-02-03

## 🔄 브랜치 병합 및 충돌 해결 (Merge `origin/develop` into `frontend`)

### 🎯 목표
기존 `frontend` 브랜치의 UI 작업물과 `origin/develop` 브랜치의 최신 게스트 기반 시스템을 동기화하고, 프로젝트 방향성(Phase 1: Guest Login)에 맞게 충돌을 해결함.

### 🛠️ 주요 해결 및 변경 사항

#### 1. API 서비스 (`api.ts`)
- **충돌 원인**: 기존 `userLogin` (회원 기반)과 새로운 `guestLogin` (게스트 기반)의 충돌.
- **해결**: 프로젝트의 최신 사양인 **`guestLogin`**으로 통일하고 미사용 `userLogin` 제거.

#### 2. 사용자 상태 관리 (`userStore.ts`)
- **구조 개선**: 유저 식별자를 `id` 방식에서 **`playerId`** (게임/웹소켓용 필수) 및 **`userId`** (회원용 선택) 체계로 변경.
- **로직 전환**: 가짜 데이터(Mock) 기반 로그인 로직을 삭제하고, 실제 API 통신을 수행하는 `guestLogin` 기반으로 교체.
- **안정성 강화**: `restoreUser` 함수에 `normalizeProfile` 로직을 추가하여, 브라우저 새로고침 시에도 구버전 필드와 신버전 필드가 호환되도록 보완.

#### 3. API 타입 정의 (`docq-api.ts`)
- **타입 정리**: 아직 구현되지 않은 회원가입(`SignUp`) 및 회원 로그인 관련 가상의 타입들을 제거하고, 실제 백엔드 연동에 필요한 **Guest 관련 타입**들로 일원화.

#### 4. 메인 로비 UI (`MainView.vue`)
- **식별자 동기화**: 닉네임 수정 시 사용되던 식별자를 `userId`에서 **`playerId`**로 변경.
- **API 연동**: 닉네임 변경 시 백엔드의 실제 닉네임 변경 API(`updateGuestNickname`)를 호출하도록 연결.
- **검증 유지**: 프론트엔드에 존재하던 닉네임 중복 체크 UI 로직을 유지하면서 API와 결합.

#### 5. 대기실 UI (`WaitingView.vue`)
- **웹소켓 연동 최적화**: 에러 구독, 게임 시작, 퀵메시지 등 모든 통신 식별자를 **`playerId`**로 통일하여 백엔드 사양과 일치시킴.
- **인증 체크**: 유저 복구 및 게임 시작 전 유효성 검사 로직이 `playerId`를 기준으로 동작하도록 수정.

### ✅ 최종 결과
- `frontend` 브랜치가 `develop` 브랜치의 **게스트 중심 아키텍처**와 완전히 동기화됨.
- 모든 API 통신 및 상태 관리가 `playerId`를 중심으로 일관성 있게 동작하도록 정리 완료.
