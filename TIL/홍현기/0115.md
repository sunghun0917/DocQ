# 오늘의 TIL
### WebSocket이란?
WebSocket은 클라이언트와 서버가 하나의 연결을 계속 유지하면서 양방향 통신을 할 수 있는 프로토콜이다.

기존 HTTP가
 요청(Request) → 응답(Response) → 연결 종료
방식이라면,

WebSocket은
 연결(Connection) → 양방향 실시간 데이터 송수신
방식이다.

즉, 실시간 통신을 위한 표준 프로토콜이다.

### 왜 WebSocket이 필요한가?
HTTP의 한계

HTTP는 기본적으로 클라이언트가 요청해야만 서버가 응답 가능하다.

그래서 실시간 서비스를 만들기 위해서는:

- 주기적 폴링(Polling)

- 롱 폴링(Long Polling)

같은 비효율적인 방식이 필요했다.

문제점:

- 불필요한 요청 많음

- 서버 부하 증가

지연 발생

이 문제를 해결하기 위해 등장한 것이 WebSocket.

### WebSocket의 핵심 특징
| 특징 | 설명 |
|--------|--------|
| 양방향 통신 | 서버 → 클라이언트도 즉시 전송 가능 |
| 연결 유지 | 한 번 연결 후 계속 사용 |
| 낮은 오버헤드 | HTTP 헤더 반복 전송 없음 |
| 실시간 처리 | ms 단위 응답 가능 |
