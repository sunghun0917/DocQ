# 📘 Prefork / Worker 모델 정리 (공부 기록)

## 1️⃣ Prefork / Worker는 무엇인가

Prefork와 Worker는 **Apache HTTPD의 MPM(Multi-Processing Module)** 방식이다.
즉, **요청을 어떻게 병렬로 처리할 것인가에 대한 서버 프로세스 모델**이다.

---

## 2️⃣ Prefork 모델

### 🔹 개념

* 서버 시작 시 **여러 개의 자식 프로세스를 미리 생성**
* **요청 1개 = 프로세스 1개**가 처리
* 프로세스 간 **메모리 공유 없음**

```
Parent Process
 ├─ Child Process 1 (요청 1)
 ├─ Child Process 2 (요청 2)
 ├─ Child Process 3 (요청 3)
```

---

### 🔹 특징

* **높은 안정성**

  * 한 프로세스가 죽어도 다른 프로세스에 영향 없음
* **스레드 안전성 문제 없음**
* **메모리 사용량 큼**

  * 동접 증가 = 프로세스 증가

---

### 🔹 왜 “Prefork”인가

* 프로세스 생성 비용이 크므로
* 요청 전에 **미리(fork) 생성**해두는 구조

---

### 🔹 사용 사례

* Apache + mod_php
* 스레드 안전하지 않은 라이브러리 사용
* 안정성 우선 환경

---

## 3️⃣ Worker 모델

### 🔹 개념

* **자식 프로세스 + 다수의 스레드**
* **요청 1개 = 스레드 1개**가 처리
* 같은 프로세스 내에서 **메모리 공유**

```
Parent Process
 ├─ Child Process
 │    ├─ Thread 1 (요청 1)
 │    ├─ Thread 2 (요청 2)
 │    └─ Thread 3 (요청 3)
```

---

### 🔹 특징

* **메모리 효율적**
* **동시 처리량 높음**
* 스레드 안전성 필수
* 스레드 간 오류 전파 위험

---

### 🔹 사용 사례

* Apache Worker MPM
* Java WAS (Tomcat, Spring Boot)
* 스레드 안전한 환경

---

## 4️⃣ Prefork vs Worker 비교 요약

| 구분      | Prefork       | Worker       |
| ------- | ------------- | ------------ |
| 병렬 단위   | 프로세스          | 스레드          |
| 요청 처리   | 1 요청 = 1 프로세스 | 1 요청 = 1 스레드 |
| 메모리 사용  | 높음            | 낮음           |
| 안정성     | 매우 높음         | 중간           |
| 스레드 안전성 | 필요 없음         | 필수           |
| 성능/동접   | 낮음            | 높음           |

---

## 5️⃣ Prefork / Worker의 한계

* 동접이 늘수록 **프로세스/스레드 수 폭증**
* 컨텍스트 스위칭 비용 증가
* WebSocket, SSE 같은 **장시간 연결에 부적합**

👉 이 한계를 해결한 게 **Nginx의 이벤트 기반 모델**

---

## 6️⃣ Nginx와의 차이 (핵심)

| 항목           | Apache (Prefork/Worker) | Nginx  |
| ------------ | ----------------------- | ------ |
| 처리 방식        | 요청 단위                   | 이벤트 단위 |
| 동시성          | 프로세스/스레드                | 이벤트 루프 |
| 메모리          | 큼                       | 작음     |
| 장시간 연결       | 불리                      | 유리     |
| CPU-heavy 작업 | 상대적으로 안전                | 위험     |

---

## 7️⃣ 한 문장 요약 (공부 기록 마지막에 쓰기 좋음)

> **Prefork는 안정성을 위해 프로세스 단위로 요청을 처리하는 방식이고,
> Worker는 자원 효율과 동시성을 위해 스레드 단위로 요청을 처리하는 방식이다.
> 두 방식 모두 요청 수에 비례해 자원이 증가하는 구조이며,
> Nginx는 이를 이벤트 기반 모델로 개선했다.**

---

## 8️⃣ Nginx와 함께 쓰이는 이유

* Nginx: 앞단

  * 대량 연결 처리
  * SSL 종료
  * 로드 밸런싱
* WAS(Tomcat 등): 뒤단

  * 비즈니스 로직
  * 스레드 풀 기반 처리
