## Docker Compose 개요

### Docker Compose란?
- 여러 컨테이너를 하나의 파일로 정의하고 관리하는 도구
- `docker-compose.yml` 파일로 서비스 간 의존성, 네트워크, 볼륨 등을 정의
- `docker-compose up` 명령어로 모든 서비스를 한 번에 실행

### 주요 키워드
- **services**: 실행할 컨테이너들을 정의
- **volumes**: 데이터 영속성을 위한 볼륨 마운트
- **networks**: 컨테이너 간 통신을 위한 네트워크
- **depends_on**: 서비스 간 의존성 정의 (시작 순서 제어)

## 개발 환경 (Dev) 설정

### 파일 위치
`deploy/compose/docker-compose.dev.yml`

### 구성 요소

#### 1. Backend (Spring Boot)
```yaml
backend-dev:
  image: eclipse-temurin:17-jdk
  container_name: spring-dev
  command: sh -c "cd /app && ./gradlew bootRun"
  volumes:
    - ../../backend:/app
  ports:
    - "8081:8081"
```

**설명:**
- **image**: JDK 이미지 직접 사용 (빌드 없이)
- **volumes**: 소스 코드를 직접 마운트하여 실시간 반영
- **command**: `gradlew bootRun`으로 개발 모드 실행
- **ports**: 호스트의 8081 포트와 컨테이너의 8081 포트 연결

**왜 JDK를 직접 사용?**
- 개발 환경에서는 JAR 파일을 만들지 않고 소스 코드를 직접 실행
- Hot Reload를 위해 소스 코드를 볼륨으로 마운트
- 하나의 Dockerfile로 dev/prod를 구분하지 않고, docker-compose에서 처리

#### 2. Frontend (Vue.js)
```yaml
frontend-dev:
  build:
    context: ../../frontend
    dockerfile: Dockerfile.dev
  container_name: vue-dev
  volumes:
    - ../../frontend:/app
    - /app/node_modules
  expose:
    - "5173"
```

**설명:**
- **build**: Dockerfile.dev를 사용하여 이미지 빌드
- **volumes**: 
  - 소스 코드 마운트 (실시간 반영)
  - `/app/node_modules`는 별도 볼륨으로 분리 (호스트의 node_modules와 충돌 방지)
- **expose**: 내부 네트워크에서만 접근 가능 (외부 노출 X)
- **포트 5173**: Vite 개발 서버 기본 포트

**중요 설정:**
- `package.json`의 dev 스크립트: `"dev": "vite --host 0.0.0.0"`
  - `--host 0.0.0.0`: 모든 네트워크 인터페이스에서 리스닝
  - 기본값(localhost)이면 다른 컨테이너(nginx)에서 접근 불가

#### 3. Nginx (리버스 프록시)
```yaml
nginx:
  image: nginx:stable-alpine
  container_name: dev-proxy
  ports:
    - "80:80"
  volumes:
    - ../nginx/nginx.dev.conf:/etc/nginx/conf.d/default.conf
  depends_on:
    - backend-dev
    - frontend-dev
```

**설명:**
- **ports**: 호스트의 80 포트로 접근 가능
- **volumes**: Nginx 설정 파일 마운트
- **depends_on**: backend-dev, frontend-dev가 먼저 시작되어야 함

## 프로덕션 환경 (Prod) 설정

### 파일 위치
`deploy/compose/docker-compose.prod.yml`

### 구성 요소

#### 1. Backend
```yaml
backend:
  image: registry.gitlab.com/your/backend:latest
  container_name: backend
  restart: always
  env_file:
    - ../env/prod.env
```

**설명:**
- **image**: 빌드된 이미지를 레지스트리에서 가져옴
- **restart: always**: 컨테이너가 종료되면 자동 재시작
- **env_file**: 환경 변수 파일 사용

#### 2. Nginx (Frontend 포함)
```yaml
nginx:
  image: registry.gitlab.com/your/frontend:latest
  container_name: nginx
  restart: always
  ports:
    - "80:80"
  volumes:
    - ../nginx/nginx.prod.conf:/etc/nginx/nginx.conf:ro
  depends_on:
    - backend
```

**설명:**
- **image**: frontend 이미지 사용 (빌드된 정적 파일 + nginx 포함)
- **volumes**: `:ro` (read-only)로 마운트
- **nginx.conf**: 전체 설정 파일 (dev는 default.conf만)

**왜 frontend 이미지를 사용?**
- Frontend Dockerfile이 멀티 스테이지 빌드로 nginx를 포함
- 빌드된 정적 파일이 이미 nginx 이미지에 포함되어 있음

## Nginx 설정

### 개발 환경 (nginx.dev.conf)

```nginx
server {
    listen 80;

    # Vue Dev Server (Vite)
    location / {
        proxy_pass http://frontend-dev:5173;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # Spring Boot API
    location /api {
        proxy_pass http://backend-dev:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

**주요 설정 설명:**

1. **proxy_pass**: 요청을 다른 서버로 전달
   - `http://frontend-dev:5173`: Docker Compose 네트워크 내 서비스 이름 사용
   - `http://backend-dev:8081`: 동일하게 서비스 이름 사용

2. **WebSocket 지원** (Vite HMR용):
   ```nginx
   proxy_http_version 1.1;
   proxy_set_header Upgrade $http_upgrade;
   proxy_set_header Connection "upgrade";
   ```
   - Vite의 Hot Module Replacement (HMR)를 위해 WebSocket 연결 필요

3. **프록시 헤더**:
   - `Host`: 원본 호스트 정보 전달
   - `X-Real-IP`: 클라이언트 실제 IP
   - `X-Forwarded-For`: 프록시 체인 정보
   - `X-Forwarded-Proto`: 원본 프로토콜 (http/https)

### 프로덕션 환경 (nginx.prod.conf)

```nginx
events {}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    upstream backend {
        server backend:8081;
    }

    server {
        listen 80;

        # Vue 정적 파일 서빙
        location / {
            root /usr/share/nginx/html;
            index index.html;
            try_files $uri $uri/ /index.html;
        }

        # Spring Boot API 프록시
        location /api {
            proxy_pass http://backend;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
    }
}
```

**주요 설정 설명:**

1. **정적 파일 서빙**:
   ```nginx
   root /usr/share/nginx/html;
   try_files $uri $uri/ /index.html;
   ```
   - `root`: 정적 파일이 있는 디렉토리
   - `try_files`: 파일을 찾지 못하면 index.html로 폴백 (SPA 라우팅 지원)

2. **upstream**:
   ```nginx
   upstream backend {
       server backend:8081;
   }
   ```
   - 백엔드 서버를 그룹으로 정의
   - 로드 밸런싱 시 여러 서버 추가 가능

3. **dev vs prod 차이점**:
   - **dev**: Vite dev server로 프록시 (동적 서빙)
   - **prod**: 빌드된 정적 파일 직접 서빙 (정적 서빙)

## Dockerfile 분석

### Frontend - 프로덕션 (Dockerfile)

```dockerfile
FROM node:24-alpine AS build

WORKDIR /app
COPY package*.json ./
RUN npm install

COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
```

**멀티 스테이지 빌드:**
1. **build 스테이지**: Node.js로 Vue 앱 빌드
   - `npm install`: 의존성 설치
   - `npm run build`: 프로덕션 빌드 (dist 폴더 생성)
2. **최종 스테이지**: Nginx 이미지에 빌드 결과물만 복사
   - 최종 이미지 크기 최소화
   - Node.js가 포함되지 않음

### Frontend - 개발 (Dockerfile.dev)

```dockerfile
FROM node:24-alpine

WORKDIR /app
COPY package*.json ./
RUN npm install

CMD ["npm","run","dev"]
```

**설명:**
- Node.js 이미지만 사용
- 소스 코드는 볼륨으로 마운트 (실시간 반영)
- `npm run dev`: Vite 개발 서버 실행

### Backend - 프로덕션 (Dockerfile)

```dockerfile
# ===== build =====
FROM eclipse-temurin:17-jdk AS builder

WORKDIR /app
COPY gradlew build.gradle settings.gradle ./
COPY gradle/ gradle/
RUN ./gradlew dependencies || true

COPY . .
RUN ./gradlew bootJar -x test

# ===== runtime =====
FROM eclipse-temurin:17-jre

WORKDIR /app
COPY --from=builder /app/build/libs/*.jar app.jar

EXPOSE 8081
ENTRYPOINT ["java","-jar","app.jar"]
```

**멀티 스테이지 빌드:**
1. **builder 스테이지**: JDK로 JAR 파일 빌드
   - Gradle 의존성 다운로드 (캐싱 최적화)
   - `bootJar`: 실행 가능한 JAR 파일 생성
2. **runtime 스테이지**: JRE만 사용
   - JAR 파일만 복사
   - 최종 이미지 크기 최소화 (JDK 불필요)

**최적화 포인트:**
- Gradle 파일을 먼저 복사하여 의존성 캐싱
- JRE만 사용하여 이미지 크기 감소

## 주요 개념 정리

### 1. Docker Compose 네트워크
- 같은 docker-compose 파일의 서비스들은 자동으로 같은 네트워크에 연결
- 서비스 이름으로 서로 접근 가능
  - 예: `http://frontend-dev:5173`

### 2. 볼륨 (Volume)
- **bind mount**: 호스트 디렉토리를 컨테이너에 마운트
  - 개발 환경에서 소스 코드 실시간 반영
- **named volume**: Docker가 관리하는 볼륨
  - 데이터 영속성 보장

### 3. 포트 매핑
- `"8081:8081"`: `호스트포트:컨테이너포트`
- `expose`: 내부 네트워크에서만 접근 가능 (외부 노출 X)

### 4. 리버스 프록시 (Nginx)
- 클라이언트 요청을 받아서 적절한 서버로 전달
- **장점**:
  - 단일 진입점 (포트 80)
  - 로드 밸런싱
  - SSL/TLS 종료
  - 정적 파일 캐싱

### 5. 개발 vs 프로덕션 차이

| 항목 | 개발 환경 | 프로덕션 환경 |
|------|----------|-------------|
| Frontend | Vite dev server (동적) | 빌드된 정적 파일 (정적) |
| Backend | gradlew bootRun | JAR 파일 실행 |
| 소스 코드 | 볼륨 마운트 | 이미지에 포함 |
| Hot Reload | 지원 | 미지원 |
| 이미지 크기 | 큼 | 작음 (최적화) |

### 6. 문제 해결 경험

#### 문제 1: 502 Bad Gateway
- **원인**: Vite가 localhost에서만 리스닝
- **해결**: `vite --host 0.0.0.0` 설정

#### 문제 2: Nginx 기본 페이지 표시
- **원인**: nginx 컨테이너가 frontend 빌드 파일에 접근 불가
- **해결**: named volume으로 파일 공유 또는 frontend 이미지에 nginx 포함

#### 문제 3: Backend 컨테이너 종료
- **원인**: 개발 환경에서 JRE 이미지 사용 (JAR 파일 없음)
- **해결**: JDK 이미지 직접 사용 + gradlew bootRun
