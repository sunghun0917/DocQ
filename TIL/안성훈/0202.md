# TIL: SSAFY EC2 ↔ 개인 AWS RDS 연결 & Actuator/Prometheus 이슈 정리

---

## ✅ 결론 먼저 (이번 문제의 핵심 해답)

**문제는 코드가 아니라 네트워크였고, 해결의 핵심은 “공인 IP”였다.**

```
RDS를 Public로 열고
EC2의 공인 IP를 RDS Security Group에 허용하자
모든 timeout 문제가 해결됐다.
```

특히 아래 구분을 명확히 이해한 것이 결정적이었다.

| 명령                 | 의미                      | 언제 쓰나                        |
| ------------------ | ----------------------- | ---------------------------- |
| `curl ifconfig.me` | **공인 IP (인터넷에 보이는 IP)** | **RDS Public 접근, 외부 서비스 연동** |
| `hostname -I`      | **사설 IP (VPC 내부 IP)**   | 같은 VPC 내부 통신                 |

👉 **이번 상황에서는 `curl ifconfig.me`만이 정답이었다.**

---

## 1. 왜 `curl ifconfig.me`가 답이었나

### 당시 상황

* EC2: **SSAFY 계정**
* RDS: **내 개인 AWS 계정**
* 서로 **다른 계정**
* 서로 **다른 VPC**
* **VPC Peering 없음**
* RDS는 initially **Private**

이 구조에서는:

* `172.x.x.x` 같은 **사설 IP는 절대 의미 없음**
* VPC 내부 통신 자체가 불가능

따라서 유일한 방법은:

1. RDS를 **Publicly Accessible = Yes**
2. 인터넷을 통한 접근 허용
3. 이때 기준이 되는 IP는 **“EC2의 공인 IP”**

---

## 2. `curl ifconfig.me` vs `hostname -I` 차이 정확히 정리

### 🔹 `curl ifconfig.me`

```bash
curl ifconfig.me
```

* EC2가 **인터넷에서 보이는 주소**
* NAT / Internet Gateway 이후의 IP
* **RDS를 Public로 열었을 때 SG Source로 사용해야 하는 값**

예:

```
13.xxx.xxx.xxx
```

→ RDS Security Group 인바운드:

```
Custom TCP | 8888 | 13.xxx.xxx.xxx/32
```

---

### 🔹 `hostname -I`

```bash
hostname -I
```

출력 예:

```
172.26.15.66 172.17.0.1 172.18.0.1
```

의미:

* `172.26.15.xx` → EC2가 속한 **VPC 내부 IP**
* `172.17.0.x` → docker0 브리지
* `172.18.0.x` → docker-compose 네트워크

👉 전부 **사설 IP**
👉 **다른 계정 / 다른 VPC의 RDS에는 아무 의미 없음**

---

## 3. 이걸 몰라서 생긴 증상들

### Spring 로그

* `CJCommunicationsException`
* `SocketTimeoutException`
* `Communications link failure`

### 네트워크 테스트

```bash
nc -zv docq-db....rds.amazonaws.com 8888
```

결과:

```
Connection timed out
```

이건:

* DB 계정 문제 ❌
* JPA 설정 문제 ❌
* Docker 문제 ❌

👉 **라우팅 자체가 없다는 신호**

---

## 4. 최종 해결 절차 요약

### 1️⃣ RDS 설정

* **Publicly Accessible = Yes**
* 즉시 적용(Apply immediately)

### 2️⃣ RDS Security Group

Source:

```bash
curl ifconfig.me
```

결과를:

```
<공인IP>/32
```

로 인바운드에 추가

### 3️⃣ EC2에서 최종 확인

```bash
nc -zv <rds-endpoint> 8888
```

```
succeeded
```

→ 네트워크 문제 해결 완료

---

## 5. 핵심 교훈 (복습용)

> **Security Group은 “허용”이고
> VPC는 “길”이다.
> 길이 없으면 허용해도 못 간다.**

그리고,

> **Public RDS + 다른 VPC 접근에서는
> 사설 IP는 전부 버리고
> 공인 IP 기준으로 생각해야 한다.**
