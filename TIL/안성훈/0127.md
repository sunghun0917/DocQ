
# TIL – EC2에서 Spring Boot 모니터링 세팅

## 오늘 한 작업

* Spring Boot 애플리케이션에 Prometheus 메트릭 연동
* Docker Compose 환경에서 Prometheus + Grafana 구성
* EC2 서버에 배포된 환경에서 SSH 터널링으로 접근
* Docker 네트워크 기준에서 `localhost` 개념 정리

---

## Spring Boot 설정

Actuator + Prometheus 연동은 이미 되어 있었음.

```gradle
implementation 'org.springframework.boot:spring-boot-starter-actuator'
implementation 'io.micrometer:micrometer-registry-prometheus'
```

```properties
management.endpoints.web.exposure.include=health,info,prometheus
```

`/actuator/prometheus` 접근 시 메트릭 출력 확인.

---

## Prometheus 설정

Docker Compose 내부 기준으로 설정.

```yaml
scrape_configs:
  - job_name: 'spring-boot-monitor'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['backend:8081']
```

* `localhost` 사용 불가
* 서비스 간 통신은 **docker-compose service name 기준**

---

## Docker Compose 구성

* Prometheus / Grafana 포트는 외부 노출하지 않음
* `127.0.0.1` 바인딩으로 서버 내부에서만 접근 가능하게 설정

```yaml
ports:
  - "127.0.0.1:9090:9090"
  - "127.0.0.1:3000:3000"
```

---

## SSH 터널링

외부 접근은 SSH 터널로 처리.

```bash
ssh -i I14D209T.pem \
  -L 9090:localhost:9090 \
  -L 3000:localhost:3000 \
  ubuntu@i14d209.p.ssafy.io
```

* Prometheus: [http://localhost:9090](http://localhost:9090)
* Grafana: [http://localhost:3000](http://localhost:3000)

---

## Prometheus 확인

* Status → Targets
* `backend:8081` → UP

쿼리 테스트:

```promql
up
http_server_requests_seconds_count
jvm_memory_used_bytes
```

---

## Grafana 설정 중 정리된 부분

* 데이터소스 URL은 반드시:

  ```
  http://prometheus:9090
  ```

* `127.0.0.1` / `localhost` 사용하면 안 됨
  → Grafana 컨테이너 자신을 가리킴

* Grafana는 볼륨 기반 서비스
  → 이전에 만든 datasource가 남아 있어서 중복 에러 발생

기존 datasource 수정으로 해결.

---

## 정리된 개념

* Docker 환경에서 `localhost`는 항상 **자기 컨테이너**
* 서비스 간 통신은 **service name**
* Grafana는 상태를 볼륨에 저장함
* 컨테이너 재시작 ≠ 설정 초기화
