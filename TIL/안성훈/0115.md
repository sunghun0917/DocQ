# 📘 학습 기록: LSTM vs Transformer (수어·동작 인식 프로젝트 기준)

## 1. 프로젝트 맥락 정리

내 프로젝트의 핵심 조건은 다음과 같다.

* 입력:

  * MediaPipe 기반 **관절 keypoint 시계열**
  * (T × D 형태, 예: 30 × 258)
* 요구사항:

  * **실시간 또는 준실시간 처리**
  * 데이터 규모 크지 않음
  * 문장 단위보다는 **동작 단위 인식**이 우선
* 목표:

  * 수어 동작을 안정적으로 분류/해석
  * 이후 텍스트 ↔ 수어 확장 가능성 고려

이 조건을 기준으로 LSTM과 Transformer를 비교했다.

---

## 2. 구조적 차이 (핵심만)

| 구분       | LSTM                | Transformer            |
| -------- | ------------------- | ---------------------- |
| 시간 처리 방식 | 순차 처리 (t-1 → t)     | 전체 시퀀스 동시 처리           |
| 기억 방식    | hidden / cell state | Self-Attention         |
| 병렬 처리    | 불리                  | 매우 유리                  |
| 위치 정보    | 구조에 내재              | Positional Encoding 필요 |
| 데이터 요구량  | 적어도 안정              | 많을수록 유리                |

---

## 3. 내 프로젝트에서 LSTM이 유리한 이유

### 1️⃣ 짧은 시퀀스 + 실시간성

* MediaPipe 기반 입력은 보통 **20~40 프레임**
* 매 프레임 들어오는 데이터에 대해 **점진적 예측**이 필요

👉 LSTM은:

* 이전 상태만 유지하면 되므로
* **스트리밍 처리에 구조적으로 적합**

Transformer는:

* 전체 시퀀스를 다시 넣어야 의미가 있음
* 실시간 누적 예측에 비효율적

---

### 2️⃣ 데이터 규모 문제

Transformer는 본질적으로:

* 대규모 데이터
* 다양한 문맥 패턴

이 있을 때 강력하다.

현재 프로젝트에서는:

* 클래스 수 제한적
* 수어 문장보다 **단일 동작 인식** 위주

👉 이 상황에서 Transformer는 **과설계(overkill)** 가능성이 큼.

---

### 3️⃣ MediaPipe Keypoint 특성

Keypoint 데이터는:

* 이미 **강한 구조적 정보(관절 관계)**를 포함
* CNN처럼 공간 패턴을 다시 학습할 필요가 적음

LSTM은:

* 이 구조화된 입력을 시간 축으로만 잘 학습하면 됨

Transformer는:

* 모든 프레임 간 관계를 다시 계산
* 계산량 대비 이득이 크지 않을 수 있음

---

## 4. Transformer가 유리해지는 지점

### 1️⃣ 문장 단위 수어 번역

* 동작 → 단어 → 문장
* **멀리 떨어진 프레임 간 관계** 중요

👉 이 경우 Self-Attention의 장점이 명확해진다.

---

### 2️⃣ 비실시간 / 오프라인 처리

* 미리 녹화된 영상
* 배치 처리 가능

👉 병렬 처리 가능한 Transformer가 효율적.

---

### 3️⃣ 멀티모달 확장

* 손 + 얼굴 + 표정 + 시선
* 또는 수어 + 음성 + 텍스트

👉 다양한 정보 간 관계 학습에 Transformer가 강함.
