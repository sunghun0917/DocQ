# 📘 오늘 배운 것 정리

## 1️⃣ HTTPS(SSL) 적용의 본질

### ✔ 배운 핵심

* **SSL은 nginx 설정 문제가 아니라 “인증서가 있는 서버에서 실행하느냐”의 문제**
* Let’s Encrypt 인증서는 **EC2 서버의 파일 시스템에 존재**
* 인증서를 사용하는 nginx 컨테이너도 **반드시 EC2에서 실행**해야 함

### ❌ 겪은 실수

* 인증서는 EC2에 있는데
* docker-compose를 **윈도우 로컬에서 실행**
* → `/etc/letsencrypt` 경로가 컨테이너에 없음
* → nginx 즉시 종료

### ✔ 교훈

> **SSL nginx는 인증서가 있는 서버에서만 띄운다.
> 로컬/서버 환경을 섞으면 100% 문제 난다.**

---

## 2️⃣ 올바른 배포 아키텍처 구조

### ✔ 최종 정답 구조

```
Client
 └─ HTTPS(443)
      └─ nginx (전용, SSL 종료)
            ├─ frontend (nginx, 정적 파일)
            ├─ backend (Spring Boot)
            └─ ai-service (FastAPI)
```

### 핵심 원칙

* 외부 포트 노출: **nginx 하나만**
* frontend / backend / ai: **내부 서비스**
* nginx 역할:

  * SSL 종료
  * 리버스 프록시
  * 라우팅

### ✔ 배운 점

> **nginx는 “프론트가 아니다”.
> 프록시와 보안의 관문이다.**

---

## 3️⃣ nginx 설정에서의 핵심 포인트

### ✔ 중요한 설정들

* `80 → 443` 리다이렉트
* `ssl_certificate` 는 **live 경로**
* frontend는 **root로 직접 서빙 ❌**
* 반드시:

```nginx
proxy_pass http://frontend:80;
```

### ✔ 이해한 개념

* `frontend:80`은 **컨테이너 내부 포트**
* 외부 포트(80/443)와 완전히 별개

---

## 4️⃣ Docker & 실행 위치의 중요성

### ✔ 배운 핵심

* docker-compose는 **“실행한 위치의 파일 시스템”을 기준으로 동작**
* 볼륨 마운트는:

  * 로컬 → 로컬
  * 서버 → 서버
* **서로 공유 안 됨**

### ✔ 교훈

> **컨테이너 문제의 절반은
> “경로”가 아니라 “어디서 실행했는지”다.**

---

## 5️⃣ HTTPS 이후 발생한 CORS 문제

### ✔ 왜 갑자기 로그인 403?

* HTTP → HTTPS 전환
* Origin이 변경됨

  * `http://localhost:5173`
  * → `https://i14d209.p.ssafy.io`
* Spring Boot CORS 허용 목록에 없음
* → `Invalid CORS request` + 403

### ✔ 해결 방법

```java
.allowedOrigins(
  "http://localhost:5173",
  "http://localhost:3000",
  "https://i14d209.p.ssafy.io"
)
```

### ✔ 중요한 규칙

* `allowCredentials(true)` 사용 시
* `allowedOrigins("*")` ❌
* → 반드시 명시적 도메인

---

## 6️⃣ Spring Security와 CORS의 관계

### ✔ 배운 사실

* `WebMvcConfigurer`의 CORS 설정은

  * **Spring Security 사용 시 무시될 수 있음**
* Security 쓰면:

```java
http.cors().and().csrf().disable();
```

* `CorsConfigurationSource` Bean 필요

### ✔ 교훈

> **CORS는 MVC 문제가 아니라
> 보안(Security) 문제다.**

## 7️⃣ 커밋 전략 & 실무 감각

### ✔ 커밋 분리 원칙

* 구조 변경 → `chore` / `refactor`
* 환경 변화로 인한 장애 → `fix`
* SSL 도입 ≠ 무조건 fix

### ✔ 실제 사용한 메시지들

```text
chore(deploy): nginx를 전용 SSL/리버스 프록시 서비스로 분리
chore(nginx): HTTPS 설정 및 리버스 프록시 라우팅 구성
fix(cors): HTTPS 도메인에 맞게 CORS 허용 설정 수정
```
