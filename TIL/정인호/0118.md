## Redis/WS 이벤트 처리 TIL 요약

### 1) Redis ZSet (Sorted Set)
- **중복 없는 값(Member)**을 저장하면서, **Score(숫자)** 기준으로 자동 정렬되는 자료구조
- 게임 이벤트 스케줄링에 사용:  
  - **Key**: 데이터 묶음 이름 (예: `game:events`)  
  - **Member**: 실제 저장 값 (예: `{eventType:"START_QUIZ", ...}`)  
  - **Score**: 실행 시점(보통 **Unix Timestamp**) → due 이벤트를 시간순으로 꺼내기 좋음

---

### 2) Poller
- “주기적으로 확인하러 다니는 감시자”
- Redis ZSet에서 **지금 실행해야 할(due) 이벤트**를 주기적으로 조회해서 처리 로직을 실행함

---

### 3) ACK (Acknowledgement)
- 프론트가 서버에 보내는 **“연출/처리 완료 확인 신호”**
- Redis Set으로 유저별 ACK를 **중복 없이 수집**해, 모든 유저가 준비되면 다음 단계로 진행

예시:
- Key: `ack:100:ROULETTE:quiz_5`
- Value(Set): `{ "user_A", "user_B", "user_C" }`

의미:
- 100번 방에서
- ROULETTE 단계에 대해
- quiz_5의 연출 완료를 확인한 유저 ID 목록(출석부)

---

### 4) SADD
- **Set Add**
- Redis Set에 값을 추가하는 명령어  
  - 예: `SADD ack:100:ROULETTE:quiz_5 user_A`

---

### 5) SCARD
- **Set Cardinality**
- Set에 들어있는 원소 개수 확인  
  - 예: `SCARD ack:100:ROULETTE:quiz_5` → 현재 몇 명이 ACK 했는지

---

### 6) 폴백 타임아웃 (Fallback Timeout)
- ACK 누락/네트워크 문제 등 예외 상황 대비용 **강제 진행 타이머**
- 일정 시간 내 ACK가 안 오면 서버가 다음 단계로 넘어가 “게임 멈춤”을 방지함

---

### 7) 프리픽스 (WebSocket 경로 관례)
- 클라이언트/서버 메시지 경로 앞에 붙는 prefix
- 보통 역할:
  - `/app` : **클라 → 서버** (요청/명령)
  - `/topic` : **서버 → 전체 브로드캐스트**
  - `/queue` : **서버 → 개인(1:1) 메시지**
