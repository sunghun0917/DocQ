## 📘 TIL – 1월 16일

오늘은 **요구사항 정의서, 와이어프레임, 기능 명세서, API 명세서**의 정의와 각 문서가 프로젝트에서 가지는 **중요성**에 대해 학습하였습니다.
요구사항 정의서는 프로젝트의 방향과 범위를 명확히 하여 이해관계자 간의 혼선을 줄여주며,
와이어프레임은 화면 흐름과 사용자 경험을 시각적으로 구체화해 기획과 개발의 기준점이 된다는 점을 이해하였습니다.
기능 명세서는 각 기능의 동작을 명확히 정의하여 개발 과정에서의 해석 차이를 최소화하고,
API 명세서는 프론트엔드와 백엔드 간의 협업을 원활하게 하는 핵심 문서임을 알게 되었습니다.

이번 학습을 통해 **명확한 문서화가 곧 개발 효율과 품질로 이어진다**는 점의 중요성을 다시 한 번 느끼는 계기가 되었습니다.

다음은 **각 문서의 정의**를 중심으로 정리한 내용입니다.

---

### 1️⃣ 요구사항 정의서 (Requirements Specification)

요구사항 정의서는 **시스템이 무엇을 해야 하는지**를 명확하게 정리한 문서입니다.
사용자와 이해관계자의 요구를 기능적·비기능적 요구사항으로 구분하여 기술하며,
프로젝트의 범위와 목표를 명확히 하여 개발 과정 전반의 기준이 됩니다.

---

### 2️⃣ 와이어프레임 (Wireframe)

와이어프레임은 **화면 구성과 사용자 흐름을 시각적으로 표현한 설계도**입니다.
각 화면에 배치될 요소들의 구조와 동선을 중심으로 표현하며,
디자인 이전 단계에서 기획 의도를 공유하고 사용자 경험을 검증하는 역할을 합니다.

---

### 3️⃣ 기능 명세서 (Functional Specification)

기능 명세서는 요구사항을 기반으로 **각 기능이 어떻게 동작해야 하는지**를 상세히 설명한 문서입니다.
입력값, 처리 로직, 출력 결과, 예외 상황 등을 명확히 정의하여
개발자 간 해석 차이를 줄이고 구현의 정확도를 높입니다.

---

### 4️⃣ API 명세서 (API Specification)

API 명세서는 **시스템 간 통신 규약을 정의한 문서**입니다.
요청 방식, 엔드포인트, 파라미터, 응답 형식, 상태 코드 등을 명시하여
프론트엔드와 백엔드 간의 원활한 협업과 안정적인 데이터 연동을 가능하게 합니다.
