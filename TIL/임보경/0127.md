# TIL (2026.01.27) — 게임 내 룰렛 결과 동기화 및 이벤트 순서 제어

## 오늘의 주제
오늘은 **게임 내 미니게임(룰렛)의 결과가 실제 서버 데이터와 일치하지 않는 문제**를 해결하고, **비동기로 일어나는 애니메이션(룰렛, 캐릭터 이동) 간의 실행 순서를 동기화**하는 로직을 구현함.

---

## 문제 상황

### 1. 룰렛 결과 불일치
- 퀴즈 정답 후 나타나는 룰렛이 클라이언트에서 단순히 랜덤하게 돌아가 멈춤.
- 서버에서 결정된 실제 이동 칸수(이벤트 결과)와 시각적인 룰렛 결과가 달라 사용자에게 혼동을 줌.

### 2. 애니메이션 비동기 실행 충돌
- 룰렛 오버레이가 사라지기도 전에 캐릭터가 이동을 시작하거나, 이동 중에 다음 퀴즈가 팝업되는 등 **게임 이벤트의 순서가 보장되지 않음.**
- 특히 `Store` 상태 업데이트와 애니메이션 실행 타이밍이 어긋나 UX를 해치는 현상 발생.

---

## 해결 과정

### 1. 서버 결과 기반의 룰렛 제어 (`RouletteOverlay.vue`)
- 단순히 랜덤으로 회전하던 로직을 제거하고, `Store`에 저장된 **서버 측 결과값(`rouletteTargetValue`)**을 받아오도록 수정.
- `watch`를 사용하여 결과값이 도착할 때까지 대기하다가, 값이 설정되면 정확히 해당 숫자에 멈추도록 **회전 각도를 역산하여 애니메이션을 적용**함.

```typescript
// 수정된 회전 로직 일부
const spinRoulette = (targetVal: number) => {
  // ...
  // 목표 숫자의 인덱스를 찾아 정확한 각도 계산
  const targetIndex = labels.indexOf(targetVal);
  const targetRotation = -(targetIndex * sectionAngle);
  
  // 현재 각도에서 목표 각도까지 부드럽게 회전 추가
  rotation.value += totalSpins + extra + targetRotation;
}
```

### 2. 애니메이션 간 동기화 (`GameBoard.vue`)
- 캐릭터 이동 로직 내에 **룰렛 실행을 대기하는 `await` 포인트**를 추가.
- `waitForRouletteStart`와 `waitForRouletteEnd` 헬퍼 함수를 구현하여, 룰렛 오버레이가 켜지고 꺼질 때까지 캐릭터 이동을 보류함.

```typescript
// 이동 로직 내 동기화
if (rouletteStep) {
    // 1. 룰렛이 뜰 때까지 대기
    await waitForRouletteStart()
    
    // 2. 룰렛에 실제 결과값 주입 (회전 시작)
    gameStore.setRouletteTargetValue(rouletteStep.value)
    
    // 3. 룰렛 애니메이션 종료 대기
    await waitForRouletteEnd()
}
// 4. 이후 캐릭터 이동 시작
```

### 3. 이벤트 큐(Queue) 처리
- 캐릭터가 이동 중일 때 새로운 퀴즈 데이터가 들어오면 바로 띄우지 않고 `pendingQuiz`에 저장.
- 이동이 완료된 시점(`setMovementInProgress(false)`)에 큐를 확인하여 대기 중인 퀴즈를 실행하도록 처리.

## 배운 점
- **시각적 요소와 데이터의 일치**: 사용자에게 보여지는 애니메이션(룰렛)은 단순 연출이 아니라 **서버 데이터의 시각화**여야 한다는 점을 다시 확인.
- **비동기 흐름 제어**: `setTimeout`이나 단순 감시(`watch`)만으로는 복잡한 애니메이션 순서를 맞추기 어렵고, `Promise`와 `await`을 활용한 명시적인 대기 로직이 훨씬 안정적임을 깨달음.
- **상태 관리의 역할**: 컴포넌트 간 직접 통신(Emit/Props)보다 `Pinia Store`를 통해 상태(`rouletteTargetValue`, `movementInProgress`)를 공유하는 것이 복잡한 게임 로직에서는 훨씬 효율적이었음.
