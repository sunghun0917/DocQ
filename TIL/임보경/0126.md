# TIL (2026.01.26) — 3D 모델 포맷 변환 이슈와 코드 레벨 제어

## 오늘의 주제
오늘은 **FBX 3D 애니메이션 파일을 GLB로 변환하는 과정에서 발생한 문제**를 해결하고, 툴(Blender)이 아닌 **코드 레벨에서 3D 모델의 불필요한 요소를 제어**하여 해결한 과정을 정리함.

---

## 진행 과정

### 1. FBX를 GLB로 변환 시도
- 웹 환경에서의 최적화와 호환성을 위해 기존 **FBX 포맷**의 애니메이션 모델을 **GLB 포맷**으로 변환하고자 함.
- 3D 모델링 툴인 **Blender**를 사용하여 Import 후 Export하는 방식을 시도함.

### 2. 변환 과정의 한계 직면
- Blender를 거쳐 변환하는 과정에서 예상치 못한 문제들이 발생함.
- 애니메이션 데이터가 유실되거나, 모델의 스케일/회전축이 틀어지는 등 **툴을 이용한 단순 변환 방식의 한계**를 확인.
- 특히 캐릭터 모델 주변에 불필요한 **바운딩 박스(캐릭터를 감싸는 박스) 메쉬**가 제거되지 않거나 의도치 않게 남는 현상이 발생함.

---

## 문제 해결

### 코드 레벨에서의 직접 제어
- Blender 등 외부 툴에서의 변환을 포기하고, **Three.js(TresJS) 코드 상에서 직접 해결**하기로 결정.
- 모델을 로드한 직후, 씬(Scene) 그래프를 순회(**Traverse**)하며 불필요한 메쉬를 찾아내어 제거하거나 숨기는 로직을 추가함.

```typescript
// 해결 코드 예시 (모델 로드 후 처리)
if (scene) {
  scene.traverse((child: any) => {
    // 이름에 'box', 'cube', 'cs_' 등이 포함된 객체를 렌더링하지 않도록 설정
    if (child.isMesh && (
      child.name.toLowerCase().includes('box') || 
      child.name.toLowerCase().includes('cube') ||
      child.name.startsWith('cs_')
    )) {
      child.visible = false; // 렌더링 제외
      child.castShadow = false; // 그림자도 제거
      child.receiveShadow = false;
    }
  })
}
```
> *실제 적용된 코드는 모델의 구조에 맞춰 traverse 로직 내에서 특정 조건을 통해 불필요한 요소를 필터링하여 처리함.*

---

## 배운 점
- **툴의 한계와 코드의 유연성**: GUI 툴에서 해결하기 어려운 문제(미세한 메쉬 제어, 데이터 유실 없는 수정)를 코드 레벨에서는 의외로 간단하게 제어할 수 있음을 깨달음.
- **Scene Graph 이해의 중요성**: `traverse` 함수 등을 통해 3D 객체의 계층 구조를 이해하고 접근할 수 있어야 원하는 요소만 골라내어 수정(`Material Clone`, `Visible` 제어 등)할 수 있음.
- **FBX vs GLB**: 웹에서는 GLB가 표준에 가깝지만, 변환 파이프라인이 확실하지 않다면 원본 FBX를 잘 핸들링하여 쓰는 것도 하나의 방법임.
