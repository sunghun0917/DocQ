# TIL (2026.01.15) — Jira 활용법과 스크럼 관리

## 🧩 Jira란?
**Jira**는 프로젝트의 진행 상황을 **시각적으로 관리하고 협업 효율을 높이는 스크럼(Scrum) 기반 프로젝트 관리 도구**
팀 단위로 업무를 분류하고, 일정한 개발 주기(Sprint)를 통해 목표를 조직적으로 달성 가능

---

## 🚀 스크럼(Scrum) 개요
- 반복 주기(Sprint) 단위로 개발을 진행하며, 매 주기마다 완성 가능한 결과물을 목표로 함
- Jira는 이러한 스크럼 관리 과정을 **시각적 보드**로 지원
  (예: To Do → In Progress → Done)

---

## 🧰 Jira 기본 구조 및 설정

### 계층 구조 (Hierarchy)
- **Epic**: 큰 기능 단위나 주제 (예: 백엔드, 프론트엔드, 디자인 등)
- **Backlog(Task)**: Epic 하위의 세부 업무 (예: ERD 설계, 와이어프레임 작성 등)

### 작성 규칙 (Convention)
- 백로그 생성 시 역할 기반으로 명명하면 관리가 쉬움
  예: `[기획] 사용자 플로우 구상`, `[FE] UI 구현`, `[BE] DB 연결`

### Story Point 설정
- 작업량 및 복잡도를 수치화한 값
- **피보나치 수열 (2, 3, 5, 8...)** 등을 활용하여 난이도 평가
- 포인트가 너무 크면, 업무를 더 작은 Task로 나눔

---

## 🧩 스프린트(Sprint) 진행 과정

1. **백로그 정리**
   - 해야 할 일을 등록하고 Epic과 연결
   - 담당자를 지정해 책임 구분

2. **스프린트 계획**
   - 이번 주에 수행할 Task를 스프린트로 묶어 시작

3. **업무 진행 관리**
   - 보드 상에서 To Do → In Progress → Done 단계로 이동

4. **번다운 차트(Burndown Chart)**
   - 완료된 업무량이 늘수록 그래프가 **우하향**
   - 프로젝트의 진척 속도를 판단할 수 있는 핵심 지표

---

## 📊 Jira 활용 포인트
- **업무 시각화:** 현재 진행 상황을 한눈에 파악 가능
- **공동 책임 분배:** 담당자 지정으로 역할 명확화
- **생산성 측정:** 번다운 차트를 통해 팀의 개발 속도 추적
- **지속적 개선:** 남은 작업량과 계획 대비 현황 비교 가능

---

## 📝 오늘의 회고
- Jira는 단순한 일정 관리가 아니라 **협업 흐름과 생산성 개선의 도구**라는 점을 배움
- 특히 **번다운 차트 관리의 중요성**을 이해하며, 스프린트 효율성을 높이는 방법을 익힘
- 다음 스프린트에서는 Story Point를 명확히 산정해 **업무 계획의 정확도**를 높이고자 함
