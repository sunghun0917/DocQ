# TIL (2026.01.21) — TypeScript 마이그레이션 및 타입 에러 해결

## 오늘의 주제
오늘은 **기존 JavaScript 기반 3D 보드게임 코드를 TypeScript로 마이그레이션하고, 엄격한 타입 체크 환경에서 발생하는 에러들을 해결**하는 작업을 진행함.

---

## 진행 과정

### 1. TypeScript 마이그레이션 준비
- 기존에 작성한 Vue 컴포넌트들(`Board.vue`, `Tile3D.vue`, `Character.vue`, `Roulette.vue`)과  
  Composable(`useIsometric.js`)을 TypeScript로 변환하기로 결정함.
- 각 파일에 **상세한 한글 주석**을 추가하여 코드 이해도를 높이고,  
  이후 팀원들과의 협업 및 유지보수를 용이하게 함.

### 2. 핵심 파일 TypeScript 변환
- **`useIsometric.ts`**: 2D 그리드 좌표를 3D 월드 좌표로 변환하는 유틸리티 함수.  
  - 반환 타입을 `[number, number, number]`로 명시하여 타입 안정성 확보.
  - `IsometricUtils` 인터페이스를 정의하여 함수 시그니처 명확화.

- **`Tile3D.vue`**: 3D 타일 컴포넌트.  
  - Props 타입을 `defineProps<{ x: number, y: number, type: number }>()`로 명시.
  - 텍스처 의존성을 제거하고 색상만 사용하도록 리팩토링.
  - `COLORS` 객체를 `Record<number, string>` 타입으로 정의.

- **`Board.vue`**: 게임 보드 메인 컴포넌트.  
  - `Player`, `GridItem`, `PathCoord`, `Dir` 인터페이스 정의.
  - 모든 `ref` 변수에 제네릭 타입 명시 (`ref<Player[]>`, `ref<PathCoord[]>` 등).
  - DFS 경로 생성 함수의 파라미터와 반환 타입 명시.

- **`Character.vue`**: 3D 캐릭터 컴포넌트.  
  - `withDefaults`를 사용하여 Props 기본값 설정.
  - `scene` 변수를 `THREE.Group | null` 타입으로 명시.
  - `watch` 콜백 함수의 매개변수 타입 명시 (`[newX, newY]: [number, number]`).

## 문제 상황 및 해결

### 1. 라이브러리 미설치 에러
- **문제**: `three`, `@tresjs/core`, `gsap` 등의 임포트에서 빨간 줄 발생.
- **원인**: 새 프로젝트에 해당 라이브러리들이 설치되지 않음.
- **해결**: `npm install three @tresjs/core @tresjs/cientos gsap` 및  
  `npm install -D @types/three` 실행하여 의존성 설치.

### 2. `any` 타입 사용 금지 에러
- **문제**: `Character.vue`에서 `scene.traverse((child: any) => ...)`에서 ESLint 에러 발생.
- **원인**: 프로젝트의 엄격한 타입 규칙(`@typescript-eslint/no-explicit-any`).
- **해결**:  
  ```typescript
  scene.traverse((child: THREE.Object3D) => {
    if ((child as THREE.Mesh).isMesh) {
      const mesh = child as THREE.Mesh
      // ...
    }
  })
  ```
  - `child`를 `THREE.Object3D`로 타입 지정 후, 타입 단언(`as THREE.Mesh`)으로 안전하게 처리.

### 3. `watch` 콜백 암시적 `any` 에러
- **문제**: `watch(() => [props.x, props.y], ([newX, newY]) => ...)`에서  
  `newX`, `newY`가 암시적 `any` 타입으로 추론됨.
- **해결**:  
  ```typescript
  watch(
    () => [props.x, props.y] as [number, number],
    ([newX, newY]: [number, number]) => { ... }
  )
  ```
  - 소스와 콜백 매개변수 모두 명시적으로 타입 지정.

### 4. `activePlayer` undefined 가능성 에러
- **문제**: `Board.vue`의 `moveStep` 함수에서  
  `const activePlayer = players.value[currentTurn.value]`가 `undefined`일 수 있다는 경고.
- **해결**:  
  ```typescript
  const activePlayer = players.value[currentTurn.value]
  if (!activePlayer) {
    console.error("No active player found!")
    isMoving.value = false
    return
  }
  ```
  - 명시적인 `undefined` 체크 추가.

## 배운 점
- TypeScript의 엄격한 타입 체크는 초기에는 번거롭지만,  
  **런타임 에러를 사전에 방지하고 코드 안정성을 크게 높여줌**.
- `any` 타입을 피하고 **구체적인 타입(인터페이스, 제네릭, 타입 단언)**을 사용하는 것이  
  장기적으로 유지보수에 유리함.
- Vue 3 + TypeScript 환경에서는  
  **`defineProps<T>()`, `withDefaults`, `ref<T>`, `watch` 타입 명시**가 핵심 패턴임.
- 주석을 상세하게 작성하면 타입 정의만으로는 전달하기 어려운  
  **의도와 맥락**을 명확히 할 수 있어 협업 시 큰 도움이 됨.
