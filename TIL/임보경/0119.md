# TIL (2026.01.19) — Unity 보드게임판 구현 (룰렛 + 경로 이동)

## 오늘의 주제
오늘은 Unity Asset을 활용해 **3D/2D 보드게임판을 구성하고, 룰렛 결과에 따라 캐릭터가 경로를 따라 이동하는 시스템**을 구현함.

---

## 진행 과정

### 1. 에셋 다운로드 및 보드판 구성
- Unity Asset Store에서 **판 에셋(fbx, glb, png)**과 **캐릭터 에셋(png)**을 다운로드함.
- 해당 에셋을 이용해 **3D 게임판**과 **2D 게임판**을 각각 구성함.
- 보드판 안에서 캐릭터가 이동할 **경로(Path)를 노드 형태로 지정**함.

### 2. 룰렛 시스템 구현
- 룰렛 UI를 제작하고, 회전 후 결과값(숫자)을 반환하도록 구현함.
- **룰렛 결과만큼 캐릭터가 경로를 따라 이동**하도록 로직을 작성함.
- 캐릭터가 이동할 **경로를 랜덤으로 선택**하는 기능을 추가로 시도함.

---

## 문제 상황 및 수정

- 초기 구현에서는 **룰렛 회전 결과(포인터가 가리키는 숫자)**와  
  실제 캐릭터가 이동한 칸 수가 서로 일치하지 않는 문제가 발생함.
- 회전 각도 계산과 인덱스 매핑 과정에서 오차가 생긴 것으로 추정됨.
- 룰렛이 멈출 때 **포인터가 실제 결과 숫자에 정확히 정렬되도록 회전 로직을 수정**하여,  
  룰렛 결과와 캐릭터 이동 칸 수가 일치하도록 개선함.

---

## 배운 점
- 보드게임형 이동 로직 구현 시,  
  **경로(노드) 정의 → 인덱스 기반 이동 → 랜덤 이동 로직**의 흐름이 중요함.
- 룰렛처럼 **회전 + 결과 값 매핑 UI**는  
  각도·섹터·인덱스 간의 관계를 명확히 정의해야 버그를 줄일 수 있음.
- 2D/3D 판 모두 같은 개념(노드 경로 + 이동 횟수)을 공유할 수 있어,  
  이후 확장성 있는 구조 설계가 필요함.

---

## 오늘의 회고
- 에셋을 활용해 **보드판과 경로, 룰렛까지 하나의 흐름으로 연결**해본 점이 의미 있었음.
- 단순히 “돌리고 움직인다” 수준이 아니라,  
  **UI 결과와 실제 게임 로직을 정확히 동기화하는 것의 중요성**을 체감함.
- 이후에는 코드 구조를 더 정리해서,  
  여러 말(캐릭터)과 여러 플레이어에도 확장 가능한 형태로 발전시키고 싶음.
