# TIL (2025.01.22) — 게임 UI 복구/통합 및 백엔드 타이밍 이슈 분석

## 오늘의 주제
**누락된 핵심 게임 UI 컴포넌트(퀴즈, 룰렛, 정답 확인)를 복구하여 `GameView`에 통합하고, 게임 시작/진행 간 발생하는 타이밍 이슈를 분석**하는 작업을 진행함.

---

## 진행 과정

### 1. 핵심 UI 컴포넌트 복구 및 통합
- 기존에 하드코딩 되어 있거나 누락되었던 게임 UI 요소들을 독립된 컴포넌트로 복구 및 연동.
- **`GameView.vue`**:
  - `QuizOverlay.vue`: 퀴즈 출제 화면 표시.
  - `RouletteOverlay.vue`: 룰렛 애니메이션 표시.
  - `AnswerFeedback.vue`: 정답/오답 결과 피드백.
  - 기존의 인라인 퀴즈 로직(`selectedOption`, `isSubmitted` 등)을 제거하고, 위 컴포넌트들이 `gameStore`의 상태에 따라 조건부 렌더링되도록 수정.

### 2. 게임 시작 내비게이션 수정
- **`WaitingView.vue`**:
  - 게임 시작 시 `GameView`로 넘어가지 않는 문제 해결.
  - `roomInfo.status`가 `STARTING`, `PLAYING`, `QUIZ_TIME` 중 하나일 경우 즉시 이동하도록 감시 로직(`watchEffect`) 강화.

### 3. 백엔드 로직 분석
- **`GameService.java`**:
  - 프론트엔드 애니메이션(약 5초 소요)이 끝나기 전에 다음 퀴즈 데이터가 도착하는 현상 원인 파악.
  - 백엔드의 `TURN_PREP_DELAY_MS`가 **1.5초(1500ms)**로 설정되어 있어, 프론트엔드 연출 시간보다 현저히 짧음을 확인.
  - 짝수/홀수 라운드에 따른 미니게임 트리거 시 `/result` 메시지가 전송되지 않는 로직 발견.

---

## 문제 상황 및 해결

### 1. UI 컴포넌트 파편화
- **문제**: `GameView` 내부에 퀴즈 표시 로직이 하드코딩되어 있어 유지보수가 어렵고 가독성이 떨어짐.
- **해결**:
  - 기능별로 컴포넌트를 분리(`QuizOverlay`, `RouletteOverlay`)하여 재사용성과 코드 가독성을 확보.
  - `GameView`는 이들의 컨테이너 역할만 수행하도록 구조 개선.

### 2. 게임 흐름 불일치 (Timing Mismatch)
- **문제**: 룰렛이 돌고 있는데 다음 퀴즈가 화면을 덮어버리는 현상.
- **분석**: 백엔드는 1.5초 뒤 다음 퀴즈를 보내지만, 프론트엔드는 룰렛/결과창 표시에 5초 이상이 필요함.
- **방향성**: 백엔드 수정을 기다리기보다, **프론트엔드에서 데이터를 큐(Queue)에 담아두고 연출이 끝난 후 처리하는 방식**으로 해결하기로 결정 (01.23 진행 예정).

---

## 배운 점
- **컴포넌트 분리의 중요성**: 거대한 하나의 뷰 파일보다 기능 단위로 쪼개진 컴포넌트 구조가 상태 관리와 디버깅에 훨씬 유리함을 재확인함.
- **프론트-백엔드 타이밍 조절**: 실시간 게임에서는 단순히 데이터를 받는 즉시 그려주는 것이 아니라, **사용자 경험(UX)을 고려한 연출 시간 확보**가 필수적임.

---

## 오늘의 회고
- 사라진 UI들을 하나씩 되살려 화면에 띄웠을 때의 안도감이 컸다.
- 단순히 "화면이 안 나온다"는 현상을 넘어, 백엔드 코드까지 열어보고 **1.5초**라는 구체적인 원인을 찾아낸 점이 뿌듯했다.
- 내일은 이 타이밍 문제를 해결하기 위한 '대기열(Queue)' 시스템을 구현해야겠다.
